# T-001 - App renders a fixed dark theme that matches the black ground

- **Status:** pending
- **Depends on:** -
- **Blocked by decision:** D-001 (DoD approval)
- **Attempts:** 0 / 3
- **Declared File Scope:** `app/src/main/java/com/example/skeleton/ui/theme/Theme.kt`, `app/src/main/java/com/example/skeleton/ui/theme/Color.kt`
- **Model Tier:** Fast

## Description

`core/CoreLayout.kt:38` always paints black and `customizedTextStyle` defaults to white, but `MyApplicationTheme`
follows system light/dark and Android 12+ dynamic colour, so theme-coloured text/icons can be dark-on-black in
light mode (A-005). Make `MyApplicationTheme` always use one explicit dark `ColorScheme`: no dynamic colour, no
light scheme, and every Material 3 colour role assigned explicitly from named tokens in `Color.kt`
(`background`/`surface` black family, `onBackground`/`onSurface` white-ish, a blue `primary` such as `#35A0F5`
with a legible `onPrimary`, `primaryContainer`/`onPrimaryContainer` with ≥ 4.5:1 contrast, `error`, `outline`, surface containers).
Keep the function signature source-compatible for existing callers (`MyApplicationTheme { }`); parameters may
remain but must not change the scheme.

## Acceptance

- `MyApplicationTheme` returns the same dark scheme regardless of `darkTheme` / Android version.
- Every role of `darkColorScheme(...)` is passed explicitly; tokens live in `Color.kt` with KDoc.
- Maps to DoD 1 and 14.
