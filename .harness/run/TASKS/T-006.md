## Description

Human report (phone CPH2895, Android 16): every behaviour works, but no album cover appears on Now Playing, and the
notification card is treated as affected too. Cause (engine diagnosis, not yet device-proved — `adb shell content …`
is not an allowed command): both paths read the legacy `content://media/external/audio/albumart/<albumId>` address —
`NowPlayingArtwork` through `openInputStream`, and Media3's default bitmap loader through `MediaMetadata.artworkUri`.
On Android 10+ that endpoint is often empty; scoped storage replaced it with `ContentResolver.loadThumbnail`.

Fix, with **no new dependency** (DoD constraint):

1. `data/mapper/AlbumArtUri.kt`: add `albumIdFromAlbumArtUri(uri: String?): Long?` — plain Kotlin, the inverse of
   `albumArtUriFor` (`".../albumart/42"` → `42`; `null`, another address, a non-number or `<= 0` → `null`).
2. `data/albumart/AlbumArtLoader.kt`: one blocking, never-throwing function that returns a downsampled `Bitmap?` for a
   song, trying in order and stopping at the first picture:
   a. API 29+: `contentResolver.loadThumbnail(<album uri from MediaStore.Audio.Albums.EXTERNAL_CONTENT_URI + albumId>,
      Size(side, side), null)`;
   b. API 29+: `contentResolver.loadThumbnail(<the song's audio content uri>, Size(side, side), null)` when known;
   c. `MediaMetadataRetriever` on the song's audio uri → `embeddedPicture` → decoded with `inSampleSize`;
   d. the legacy `openInputStream(albumart uri)` decode (the current code; the only path on API 24–28).
   Re-throw `CancellationException`; catch `Exception` and `OutOfMemoryError`; `Log.w` once per failed song; always
   `release()` the retriever. Move `calculateInSampleSize` here from `NowPlayingArtwork.kt`.
3. `NowPlayingArtwork`: take the song's audio `contentUri` as well, key the `produceState` on both, and call the loader
   on `Dispatchers.IO`. Keep the placeholder, sizing (`aspectRatio(1f)`) and look exactly as they are.
   `NowPlayingFragment.kt`: pass `song.contentUri` — no other change.
4. Notification: `service/AlbumArtBitmapLoader.kt` implements Media3's `androidx.media3.common.util.BitmapLoader`
   (`@UnstableApi`, opt in with `@androidx.annotation.OptIn(UnstableApi::class)`): `loadBitmap(uri)` — for an album-art
   address use `albumIdFromAlbumArtUri` + the loader (steps a, c via one song of that album found with a MediaStore
   query on `ALBUM_ID`, then d); `decodeBitmap(bytes)` — `BitmapFactory` decode (ExoPlayer's embedded artwork arrives
   as `artworkData`); run on a single background executor and return a `ListenableFuture` (Guava's
   `SettableFuture` / `Futures` are already on the classpath through Media3 — the build is the judge; if not, use
   `androidx.concurrent.futures.CallbackToFutureAdapter` only if already present, otherwise report it). Install it with
   `MediaSession.Builder(...).setBitmapLoader(...)` in `MusicPlaybackService.onCreate` and shut its executor down in
   `onDestroy`. `MediaItemMapper.kt` keeps `setArtworkUri` unchanged (DoD #4).
