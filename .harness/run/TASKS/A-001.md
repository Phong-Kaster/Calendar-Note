## Description

Put an Alarms screen in the app and make it reachable. Nothing is stored yet: the ViewModel holds an empty
list and the screen shows its empty state. The ViewModel exists because the house screen spine requires one,
not because it does anything yet.

Build the standard spine — `AlarmsFragment : CoreFragment()` with `by viewModel()`, a private
`AlarmsLayout(uiState, on…: () -> Unit = {})` that navigates nowhere, `AlarmsUiState` as a data class with
every field defaulted, `AlarmsViewModel` with an instance `private val TAG` and
`_uiState.value = _uiState.value.copy(...)` updates. Copy `CalendarFragment` for the shape.

Use `CoreLayout`, with `topBar = { CoreTopBar(title = …) }` and `bottomBar = { CoreBottomBar(...) }`. Leave
`CoreLayout`'s `floatingActionButton` slot empty for now — A-002 fills it, because a FAB that opens nothing
is not a checkpoint.

The empty state is a centred sentence in the content area, not a blank region. `HomeNoteList`'s empty state
is the thing to match, so the two read as the same deliberate choice.

The `ic_bottom_alarm.xml` drawable: copy `ic_bottom_calendar.xml`'s shape — a 25dp stroke vector whose
`strokeColor` is overridden by `Icon(tint = …)` at the call site.

**The Iteration handles, and you must not touch:** `domain/enums/BottomBarDestination.kt` (the fourth entry),
`res/navigation/navigation_graph.xml` (`alarmsFragment` + a `toAlarms` action shaped like `toCalendar`),
`injection/ViewModelModule.kt`, both `strings.xml` files, `ui/component/CoreBottomBar.kt` (hiding the
centre "+" on this screen, per AS-5), `README.md`, and the re-record of the bottom-bar reference images.

**Report, do not write:** every new string key with its English text and a German translation.
