## Description

1. **Seek while paused is seen.** A seek from outside the screen (lock screen, Quick Settings, notification seek bar)
   while paused changes nothing in `NowPlaying`, so `StateFlow` drops it and the slider stays stale. Make the
   repository publish position discontinuities (e.g. `Player.Listener.onPositionDiscontinuity` → a counter or
   position snapshot in `NowPlaying`), and have the ViewModel re-read the position on it.
2. **Empty restore / failed connect closes the screen.** Today the screen closes only after it has seen a song and
   lost it; after process death with Now Playing restored, or a failed controller build, it shows an empty screen.
   Expose "connection attempt finished" (e.g. `NowPlaying.isConnected` or a separate state) and close when connected
   with no song, as well as when a seen song goes away. Must not close during the brief initial state before connect.
3. **No ticking off-screen.** The ~500 ms poll must run only while the screen is at least STARTED (e.g. Fragment
   calls `onScreenStarted()` / `onScreenStopped()` from lifecycle, or `repeatOnLifecycle(STARTED)`), and restart on
   return, re-reading the position at once.
4. Remove the unused `TAG` in `NowPlayingViewModel` (NIT).

Keep C-07 (main thread), C-08 (one connect/one release per ViewModel), C-12 unchanged.
