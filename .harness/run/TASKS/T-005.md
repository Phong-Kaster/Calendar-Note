## Description

Introduce a plain-Kotlin, Android-free `CalendarMonth` (wrapping `java.time.YearMonth`, no
`@RequiresApi` needed since it is JVM-testable and desugaring covers device use — see
`core/extension/date_and_time/LocalDateExtension.kt` for the existing `@RequiresApi` convention used on
Android-facing code, which this domain model deliberately does not need): `previous(): CalendarMonth`,
`next(): CalendarMonth`, `lengthOfMonth(): Int`, and a `buildGrid(): List<LocalDate?>` producing
leading/trailing `null`s so a 7-column grid aligns on the correct weekday.

Build the Calendar screen shell: `CalendarFragment` (extends `CoreFragment`), `CalendarViewModel` holding
the current `CalendarMonth` in `CalendarUiState`, `CalendarMonthHeader` (month/year label + prev/next
arrows), `CalendarMonthGrid` (7-column grid using `CalendarDayCell`), today's date highlighted. No notes
yet — `CalendarDayCell` takes a `hasNotes: Boolean` parameter now (default `false`) so T-006 can wire it
without touching this file's structure.

## Acceptance

- Opening the Calendar screen shows the current month; tapping previous/next moves one month at a time.
- `CalendarMonthTest`: `YearMonth.of(2025, 1).previous()` == December 2024; `YearMonth.of(2024, 2)` (leap
  year) has 29 days; `YearMonth.of(2023, 2)` has 28 days; `next()` from December rolls into January of the
  following year.
- Maps to DoD criteria 8, 9, 17, 18.
