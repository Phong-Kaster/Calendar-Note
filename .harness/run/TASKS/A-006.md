## Description

An alarm the user saved, that looks armed in the list, and that the operating system will never deliver, is
the quietest failure this feature has. The list cannot tell the difference; only the permission state can.

Two independent conditions, reported separately because they are fixed on different system screens:

1. **Notifications are off for the app** — `isNotificationGranted(context)` already exists in
   `ui/fragment/home/component/HomeRequestPermission.kt`, and so does `openAppSettings(context)`.
2. **Exact alarms are not permitted** — `canScheduleExactAlarm(context)` and `requestExactAlarm()` are in
   the same file.

**Read those existing top-level helpers. Do not query the scheduler for its state** — A-006 shares Phase 5
with A-005, which owns `domain/scheduler/` and `data/scheduler/`, and the disjointness that makes the two
safe to run at once holds only if you stay out of those packages.

`AlarmsPermissionNotice` is a banner above the list, not a dialog: it must not block a user who is only
looking. Each condition gets its own line with its own action control, and the control goes to **the right
system screen** — app settings for notifications, the exact-alarm request for exact alarms. A notice
offering one fix for two different problems is a worse failure than no notice.

**It must clear itself.** Re-read both conditions when the screen resumes, not once at `init` — the user
leaves the app, changes the setting, and comes back, and a warning still sitting there reads as the app
being broken. Drive it off the Fragment's lifecycle and push the result into the ViewModel's state.

The condition flags live on `AlarmsUiState` as plain `Boolean`s set through a function the ViewModel
exposes, which is what makes the ViewModel testable: the helpers need a `Context` and would return `false`
vacuously under the JVM toolchain (C-06), so the *reading* happens in the Fragment and only the *state* is
tested.

Colour from the theme only (C-01) — the warning uses an error or tertiary role, computed against the black
ground rather than judged by eye. Every `Text` through `customizedTextStyle(...)` (C-11).

**The Iteration handles, and you must not touch:** both `strings.xml` files, `AlarmsScreenshotTest.kt`,
`README.md`.

**Report, do not write:** every new string key with its English text and a German translation.
