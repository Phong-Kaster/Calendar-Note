## Description

`PROJECT.md` currently describes a repository with **no** notification and alarm infrastructure — it says
so in as many words, and it will be wrong the moment A-004 lands. This task makes it true again.

What must change, at minimum:

- **Environmental Facts** — "Notification and alarm infrastructure is 100% absent" is no longer true.
  Replace it with what now exists: the channel and where it is created, the receivers and what they hear,
  the scheduler seam and why it is a seam.
- **Architecture Conventions** — `AppDatabase` is no longer at `version = 3`. The bottom bar is no longer
  three tabs. `CoreLayout`'s `floatingActionButton` slot is no longer unused by anything.
- **Toolchain** — the unit-test count, the lint summary and the screenshot case count all moved. Quote
  numbers only from a run whose own `BUILD SUCCESSFUL` line you were shown; a count that did not move after
  tests were added is proof the task did not run, not proof of a pass.
- **Constraints** — add a `C-xx` entry for anything this run discovered that would make a future Worker
  **wrong** rather than merely untidy. Each entry carries its evidence: the iteration, the command, what
  actually happened. Do not add a Constraint for something that was only annoying; the list works because
  every entry on it is a trap, and padding it is how it stops being read.

Each claim is checked against the tree as it now stands, not against what the task files said would be
built. Where they differ, the tree is right and the task file was a plan.

**The Iteration handles, and you must not touch:** `README.md` (package tree and feature table — DoD 36),
and `.harness/ISSUES.md`, which the Iteration regenerates every iteration by §10 and which therefore cannot
be in any Worker's scope. See AMENDMENTS.md A-1.
