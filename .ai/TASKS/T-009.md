## Description

- **README.** Bring `README.md` (seeded in T-001) up to date: purpose, feature list, tech stack, and
  the package tree for `app/src/main/java/com/example/skeleton/` with a purpose note per major

  gap actionable instead of merely disclosed. It is the last thing standing between the run and a
  DONE-candidate, and Final Verification reports its items as human-inspection findings rather than
  as verified criteria.

### The three acceptance checks, and what each was checked *against*

1. **README package tree vs. the real tree.** `git ls-files` over
   `app/src/main/java/com/example/skeleton/` returns **107 `.kt` files**; the README fence contains
   **107 `.kt` entries**; every path is present and every folder lists subfolders before files. The
   engine verified this package-by-package and the fresh-context reviewer re-verified it
   independently at path level — which mattered, because the throwaway script written to check it
   compared *basenames only* and would have passed a file filed under the wrong package. **Counted,
   as `STATE.md` directed, rather than trusted**: iteration 10 added
   `domain/model/FutureDateRefusedException.kt` and the README omission was caught only by counting.
2. **Strings.** 31 new keys this run, all in `res/values/strings.xml`, each with a German
   counterpart (`values-de/` = 33 additions, the extra two being T-001's clearing of the pre-existing
   baseline failure). `app_name` is `translatable="false"`, which is the whole of the 61-vs-60
   difference. All are named for their own words bar the seven `weekday_short_*` keys, whose
   qualifier is deliberate and reasoned inline in the file. The one pre-existing violation
   (`allow_exact_alarm_for_prayer_time`) was already filed and was **not** re-reported.
3. **No hardcoded user-visible text in this run's screens.** A grep for `text = "` /
   `contentDescription = "` across `ui/` returns 12 hits: **every one is in a pre-existing skeleton
   file**, and a second grep over the new screens returns only `@Preview` names, preview fixture data
   and `TAG` constants. Likewise `Color(0x…)` — **no file added by this run contains one**, which is
   criterion 2's only real evidence (a screenshot renders `Color.White` and `onBackground`
   identically).

### Reference-image state, settled by the report rather than by git

`validateDebugScreenshotTest` names the file it used, so the live set is readable:
`grep -o '[a-f0-9]\{8\}_0\.png'` over
`app/build/reports/screenshotTest/preview/debug/*.html` lists **20 hashes**, and
`git ls-files app/src/screenshotTestDebug/reference` lists **the same 20**. So every live reference
is committed and a clean clone validates — the failure mode worth checking, since a live-but-untracked
image passes here and fails there. The **8 untracked PNGs** are all dead, none of their hashes
appearing in the report. This is the method `PROJECT.md` § Toolchain prescribes after iteration 10's
review reasoned from the tracked/untracked split instead and called a live image a stray.

### Fresh-context review

**12 findings — 1 Critical, 3 Major, 8 Minor. All 12 addressed; none filed, because a documentation
defect has nowhere to be filed *to*: the wrong sentence is the deliverable.** The review verified
every filename, line number, count and code claim in the three files, and confirmed the accurate
ones as accurate — the findings are the four places the prose outran what was true.

The Critical is the one worth carrying forward. Part D of the checklist — the section headed *"what
you do **not** need to check"* — claimed the `updatedAt` ordering was **"mutation-checked at both
layers"**, meaning SQL and store. It is not, and cannot be: checking a SQL `ORDER BY` means running
SQLite, which needs an emulator this project has no setup for. `NoteRepositoryImplTest`'s own header
says so outright. **The sentence took a real, deliberate piece of defence-in-depth and reported it
as evidence, inside the one section of the document that tells a human to skip something** — the
exact inversion of `POLICIES.md` § Evidence Requirements, arrived at from the other direction. Three
of the Majors are the same species: a count stale by nine iterations (14 files/65 literals, when
T-001 had reduced it to 8/43), an item asking a human to eyeball what a byte-comparison settles, and
a step asking for a judgement of the refusal message without saying how to make one appear — which
the app is deliberately built to prevent.
