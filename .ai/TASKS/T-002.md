# T-002 — Home shows persisted notes newest-first, with an empty state

- **Status:** ✅ complete — 2026-09-10, iteration 4
- **Depends on:** T-001
- **Attempts:** 1 / 3

## Description

Give the app a real notes store and make Home read from it, replacing the demo post list. This is
the first checkpoint where the app is a note app rather than a skeleton.

- `domain/model/Note.kt` — `id: Long`, `date: LocalDate`, `title: String`, `content: String`,
  `createdAt: Long`, `updatedAt: Long` (epoch millis).
- `data/database/local/entity/NoteEntity.kt` — table `notes`. Store `date` as an epoch-day `Long`
  so the DAO can filter and sort on it without a converter; keep the mapping in the mapper, not in
  the DAO query. `title` is `TEXT NOT NULL DEFAULT ''` — it may be blank (amendment A-001).
- `data/database/local/dao/NoteDao.kt` — `observeAll(): Flow<List<NoteEntity>>` ordered by
  `updatedAt DESC`, `getById(id): NoteEntity?`, `upsert`, `delete`, `observeByDate(epochDay)`
  (used in T-007; add it now so the DAO is written once).
- Register `NoteEntity` in `AppDatabase`, bump `version` 2 → 3, write `MIGRATION_2_3` in
  `data/database/local/Migration.kt`, add it to `.addMigrations(...)` and expose `noteDao()` in
  `injection/DatabaseModule.kt`. `fallbackToDestructiveMigration(false)` means a missing migration
  crashes at launch — the migration is not optional.
- `data/mapper/NoteMapper.kt` — `NoteEntity.toDomain()` / `Note.toEntity()`.
- `domain/repository/NoteRepository.kt` + `data/repository/impl/NoteRepositoryImpl.kt`
  (Recipe B, Room-only). Expose `val notesFlow: Flow<List<Note>>`. Bind by interface in
  `injection/RepositoryModule.kt` with named arguments.
- Repoint `HomeUiState` / `HomeViewModel` / `HomeLayout` from posts to notes: collect `notesFlow`,
  render rows in the existing `LazyColumn`, add an explicit empty-state message. Leave the post and
  network plumbing wired in Koin but unused by Home.
- Row content: the note's **title**, or — when the title is blank — the first line of its body
  (amendment A-001, DoD criterion 4), plus the date and a body preview.
- Row overflow: bounded `maxLines` with ellipsis. Do not truncate to one line with no route to the
  rest — the full text is reachable by opening the note in T-004.

## Acceptance

Maps to DoD criteria 3, 4, and the list half of 12.

- `./gradlew :app:assembleDebug`, `:app:testDebugUnitTest`, `:app:lintDebug` all succeed.
- A JVM unit test against a fake `NoteDao` proves `notesFlow` emits notes ordered by `updatedAt`
  descending, for a list deliberately not inserted in that order.
- A unit test proves the row's display label: a note with a title shows the title; a note with a
  blank title shows the first line of its body. Put that fallback somewhere a test can reach — a
  derived value on the model or the UiState, not inside a `@Composable`.
- `AppDatabase` is at `version = 3` with `MIGRATION_2_3` registered; the diff shows the migration SQL.
- Home renders the empty-state string when the store is empty (the observable change on launch:
  Home no longer shows posts).
- Recorded as **needing human inspection** (class (I)): the list scrolls when it is longer than the
  screen.

### Fresh-context review — 0 Critical, 2 Major, 7 Minor

The reviewer re-derived the evidence from build artefacts rather than trusting the numbers above,
and confirmed the migration byte-for-byte against Room's generated statement.

Both **Majors were reconciliation, not code**, and both are fixed in this checkpoint:

1. `knowledge/PROJECT.md` still said `AppDatabase` is at `version = 2` and that the only unit test
   is the `ExampleUnitTest` stub. That file is read as *convention* at Orient, so a later task
   would have read "version 2" as current and bumped to 3 a second time — a version/migration pair
   Room rejects at first open, which `fallbackToDestructiveMigration(false)` turns into a launch
   crash nothing here can catch. Corrected, along with the test-surface list.
2. `knowledge/ISSUES.md` still asked for `home_refresh` and `home_no_posts` to be renamed. This
   task deleted both. The entry now covers only the surviving `allow_exact_alarm_for_prayer_time`.

Minors fixed: the demo-vertical comment in `RepositoryModule` now says that **`UserActionRepository`
also** lost its last caller (`HomeViewModel.createUser()` went with the posts); `Note.toEntity()` —
which has no production caller until notes become writable — gained a round-trip assertion;
`NoteRepositoryImpl` gained `.catch { emit(emptyList()) }` and an injected `ioDispatcher`, so a
corrupt database shows an empty list instead of killing the collector, exactly as
`.claude/repository-layer.md` § Fail-soft requires; `@author` moved out of two inert `/* */` blocks
into real KDoc; and the row's date is now formatted with the **configuration** locale rather than
`Locale.getDefault()`, so it follows this app's own language picker instead of the device's setting.

Minors accepted, with the reason:

- **No `TAG` in `HomeViewModel`.** `.claude/viewmodel-layer.md` asks for one on every ViewModel.
  Nothing in this ViewModel logs, so a `TAG` would be an unused property and a compiler warning;
  `SettingViewModel` does not carry one either. Add it with the first `Log` call.
- **`isLoading` defaults to `true`**, against that same file's rule 4 (`= false`). Reading from
  Room is asynchronous, so a state that starts "not loading, no notes" flashes the empty-state
  message at somebody who has fifty of them. `CLAUDE.md` asks for conflicts to be named rather than
  silently resolved — this is the one, and the KDoc on `HomeUiState` carries the reason.
- **No `basicMarquee` on the single-line date.** A marquee animates; a list where every row's date
  slides sideways forever is worse than a truncation that cannot occur at this width. Same
  deviation, same reason, as `ThemeScreenshotTest.kt`.

## Deliberately not done, and what it costs

- **The rows are not clickable.** Opening a note is T-004. DoD criterion 12 asks that truncated
  text be reachable by opening the note, so criterion 12 is **half-satisfied** at this checkpoint:
  the overflow behaviour exists, the route to the full text does not yet.
- **No screenshot case pins a populated row.** A row prints its date through
  `DateTimeFormatter.ofLocalizedDate(...)`, whose output follows the rendering host's locale — a
  reference image of it fails on a machine set to German, and the only cure is
  `updateDebugScreenshotTest`, which is the command nobody may reach for. **Consequence to carry
  into T-004:** the row's "Untitled note" fallback, for a note with neither title nor body, is
  checked by no test at all. Stated in `HomeScreenshotTest.kt` where a reader will find it.
- **The empty-state case renders `HomeNoteList`, not `HomeLayout`.** `HomeLayout` is `private`, as
  the house rules require, so the screenshot source set cannot reach it. If `HomeLayout` stopped
  calling the list, or held `showLoading` true forever, Home would be blank on a device and this
  case would still pass.
- **The demo `UserAction` vertical is now dead too**, not just `Post`. Both stay wired in Koin per
  the standing assumption in `STATE.md`; the Koin module now says so out loud.

## Notes

- `HomeViewModel` currently takes `userActionRepository` and `postRepository`. Repointing it changes
  the `viewModelModule` entry — keep named arguments.
- Storing `date` as epoch-day avoids a `LocalDate` type converter and keeps `ORDER BY` / `WHERE`
  cheap. The existing `DateConverter` handles `java.util.Date`, not `java.time.LocalDate`; do not
  extend it for this.
- No test infrastructure exists yet. This is the first real unit test in the repository — if
  `testDebugUnitTest` has never run, expect to discover missing test dependencies as part of the task
  rather than as a defect.
