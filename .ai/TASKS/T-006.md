# T-006 — Calendar screen: month grid, today marked, month navigation, future days inert

- **Status:** pending
- **Depends on:** T-002
- **Attempts:** 0 / 3

## Description

Add the Calendar screen and get the month grid right before hanging any note behaviour off it.

- New screen `ui/fragment/calendar/` — `CalendarFragment`, `CalendarUiState`, `CalendarViewModel`,
  private `CalendarLayout` + `@Preview`s for the meaningful states. Reachable from the app's
  navigation: add the destination and action to `res/navigation/navigation_graph.xml` and an entry
  point (extend `BottomBarDestination` / `CoreBottomBar`, matching how Home and Setting are wired).
- Month grid for the displayed month, with weekday headers and correct leading/trailing blanks.
  Previous / next month controls.
- **The day-cell state is plain Kotlin, not a composable.** Put the mapping
  `(date, today, displayedMonth) -> DayCellState` (`Past`, `Today`, `Future`, `OutsideMonth`) in a
  testable place — `CalendarUiState` as a derived value, or a small domain helper. A rule that lives
  inside `@Composable` can only be checked by rendering it, and this repository cannot render in a
  test.
- Every day after today renders visibly disabled and ignores taps: no `clickable`, or a `clickable`
  whose `enabled` is false — not a click handler that silently does nothing, which is
  indistinguishable from a bug.
- Today is marked. Selection is marked. Check the **combined** states, not each alone: today *and*
  selected, selected *and* has-notes. A marker that repeats the fill it sits on is invisible
  (`POLICIES.md` § User-Interface Defects).
- All colours from the theme built in T-001.

## Acceptance

Maps to DoD criteria 8 and 9.

- Build, unit tests and lint succeed.
- A JVM unit test proves the day-cell state mapping: a date after today maps to `Future`, today maps
  to `Today`, a date before today maps to `Past`, and a date outside the displayed month maps to
  `OutsideMonth`. Include a month boundary (e.g. the 1st and the last day) and a leap-year February.
- A unit test proves the grid for a known month has the right number of leading blanks and the right
  day count.
- The diff shows no tap handler reachable for a `Future` cell.
- Recorded as **needing human inspection** (class (I)): a disabled future day is *legibly* disabled,
  and the today/selected/has-notes markers are distinguishable from each other and from the fill
  underneath.

## Notes

- `java.time` is available on `minSdk 24` through core-library desugaring (already enabled). Use
  `LocalDate`, `YearMonth` and `DayOfWeek` rather than `Calendar`.
- The week start day is locale-dependent. Pick one deliberately and say which in the KDoc — a grid
  that assumes Monday on a locale that starts on Sunday is off by one for every cell.
- Do not import a third-party calendar library. That would be a technology choice, i.e. Tier 2, and
  needs an escalation first.
