### Fresh-context review

16 findings across 3 severities. **0 Critical.** Three Major and five Minor were fixed in this
iteration; the rest were filed.

**Fixed here:**

- **The file's own comment claimed coverage it did not have.** It said the suite made criteria 1
  *and 2* machine-defendable. It does not cover criterion 2: a screenshot cannot tell `Color.White`
  from `colorScheme.onBackground` when both render `#FFFFFF`, and the proof is that 14 files still
  hold hardcoded literals and all six cases pass anyway. This is `POLICIES.md` § Evidence's "quiet
  narrowing" failure, and the worse half is that it was written down as if settled. The comment now
  states what the images do and do not prove; the residue is in `knowledge/ISSUES.md`.
- **README was not updated in the same change** (`CLAUDE.md` requires it, and criterion 13 names
  `validateDebugScreenshotTest`). Added: both screenshot commands, the never-re-record-to-go-green
  warning, and a test-source-set table.
- **The `inversePrimary` swatch invented a colour pairing the app never paints** — `inversePrimary`
  fill under `onPrimaryContainer` text, which measures **3.94:1**, under AA. Material uses
  `inversePrimary` as an action label *on* `inverseSurface`. Redrawn that way. A reference image
  showing a combination that will never appear on screen asks a human to approve nothing.
- Four of the 36 roles were never rendered. `surfaceTint`, `surfaceDim` and `surfaceBright` added;
  `scrim` documented as deliberately absent (it is pure black by design and only ever painted as a
  translucent veil, so a solid swatch of it on a black ground proves nothing).
- **`surfaceDim` renders indistinguishable from the ground** — correct, since `Theme.kt` assigns it
  `ColorBackgroundDark` on purpose. Its label now says so, otherwise the first person to approve
  that image reads a missing row and "fixes" the theme.
- Added the `Screen shell` case. Every other case paints the ground through `ScreenshotScaffold`,
  which is a *copy* of what `CoreLayout` does. If `CoreLayout` ever went back to hardcoding its
  background, every scaffold-based image would stay green while the real app changed underneath.
- Added the night-mode twin (above).
- `@author Phong-Kaster` added to the four preview KDocs (house rule); unused `Configuration` import
  removed, then reinstated when the night twin needed it.

**Filed, not fixed:**

- Reference images are **host-locked**: exact-pixel comparison, no `imageDifferenceThreshold`, no
  JDK toolchain pinned. → `knowledge/ISSUES.md`, together with the orphan-PNG problem below.
- Criterion 2 has no automated gate at all. → folded into the existing hardcoded-colour entry in
  `knowledge/ISSUES.md`.
- **`CoreBottomBar`'s active state is not covered.** Rendered with no `LocalNavController`,
  `currentDestination` is null, so both tabs are inactive and the bar's only `Text` — the active

  needs it (T-006, which puts Calendar on that bar). Noted below rather than filed: it is a Minor
  coverage gap, not a defect in the app.
- `room-testing` borrows `version.ref = "roomRuntime"` while `room-compiler`/`room-ktx` carry their
  own refs. Harmless today (all three are 2.7.2) and left alone rather than restructuring the
  catalogue inside an unrelated task.

The task's acceptance asks for a person to confirm, once, that the references show a dark UI with a
legible blue accent. **The engine looked at all six and reports them correct** — black ground,
`#35A0F5` accent legible on it, every label readable on its own fill, both boundary roles visible,

once, defended by a command thereafter". Collected with the rest in T-009.

## Notes

- Ordering matters: this task is **after** T-001 and **before** T-002. Imported before the theme is
  fixed, the first reference images would pin the wrong (dynamic/light-capable) theme and every later
  screenshot would be validated against a mistake.
- The screenshot tasks are granted in `knowledge/capabilities.json`
  (`:app:validateDebugScreenshotTest`, `:app:updateDebugScreenshotTest`). Host-side layoutlib on the
  JVM — no emulator, no device, no `adb`.
- `updateDebugScreenshotTest` **overwrites** reference images. Never run it to make a failing
  validation go away — that silently re-baselines the regression the test existed to catch. Run it
  only when the change to the rendering was intended, and say so in the evidence.
