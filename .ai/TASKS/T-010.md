**What to import (all four pieces are required; the harness does not work partially):**

1. `gradle/libs.versions.toml` — version `screenshot = "0.0.1-alpha15"`, library
   `screenshot-validation-api = { group = "com.android.tools.screenshot", name =
   "screenshot-validation-api", version.ref = "screenshot" }`, plugin
   `screenshot = { id = "com.android.compose.screenshot", version.ref = "screenshot" }`.
2. `app/build.gradle.kts` — `alias(libs.plugins.screenshot)` in `plugins`;
   `experimentalProperties["android.experimental.enableScreenshotTest"] = true` inside `android { }`;
   and in `dependencies`: `screenshotTestImplementation(libs.screenshot.validation.api)` +
   `screenshotTestImplementation(libs.androidx.compose.ui.tooling)`.
3. `gradle.properties` — `android.experimental.enableScreenshotTest=true`.
4. `app/src/screenshotTest/kotlin/com/example/skeleton/screenshot/ScreenshotScaffold.kt` — copy
   verbatim. It wraps content in `MyApplicationTheme` **on `colorScheme.background`**, which is the
   whole point: a bare `@Preview` renders against Studio's white with Material's baseline colours,
   which is exactly how hardcoded colours survive review.

**Also add the test dependencies granted in D-001 Q3** while `build.gradle.kts` is open:
`kotlinx-coroutines-test` and `room-testing`, both `testImplementation`. The unit tests in T-002
onward need `runTest`.

**Do not copy `TodoScreenshotTest.kt`** — that feature is not in this PRD. `CalendarScreenshotTest.kt`
is a pattern to copy in T-006/T-007, not a file to import now (it references composables that do not

**First reference images.** Write screenshot cases for what exists after T-001 — the theme applied

## Notes

- Ordering matters: this task is **after** T-001 and **before** T-002. Imported before the theme is
  fixed, the first reference images would pin the wrong (dynamic/light-capable) theme and every later
  screenshot would be validated against a mistake.
- The screenshot tasks are granted in `knowledge/capabilities.json`
  (`:app:validateDebugScreenshotTest`, `:app:updateDebugScreenshotTest`). Host-side layoutlib on the
  JVM — no emulator, no device, no `adb`.
- `updateDebugScreenshotTest` **overwrites** reference images. Never run it to make a failing
  validation go away — that silently re-baselines the regression the test existed to catch. Run it
  only when the change to the rendering was intended, and say so in the evidence.
