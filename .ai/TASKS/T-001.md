# T-001 — Dark-only theme with blue primary, app named "Calendar Note", README seeded

- **Status:** complete
- **Depends on:** —
- **Attempts:** 1 / 3

## Description

Make the app dark-only with a blue accent, so that every later screen has a correct theme to paint
from instead of reaching for colour literals.

- Rewrite `ui/theme/Theme.kt`: one fixed `darkColorScheme(...)`. Remove the `darkTheme` and
  `dynamicColor` parameters, `lightColorScheme`, `isSystemInDarkTheme()`, `dynamicDarkColorScheme`
  and `dynamicLightColorScheme`. The theme must not vary with the system setting.
- Fill **every** role of the scheme — `primary`, `onPrimary`, `primaryContainer`,
  `onPrimaryContainer`, `secondary`, `onSecondary`, `secondaryContainer`, `onSecondaryContainer`,
  `tertiary`, `onTertiary`, `background`, `onBackground`, `surface`, `onSurface`, `surfaceVariant`,
  `onSurfaceVariant`, `surfaceContainer`, `surfaceContainerHighest`, `outline`, `outlineVariant`,
  `error`, `onError`. Partial schemes leave components reaching for roles nobody chose
  (`POLICIES.md` § User-Interface Defects).
- Add the missing dark tokens to `ui/theme/Color.kt` alongside the existing `ColorBlue` / `ColorBlue2`.
  `primary = ColorBlue2` (`#35A0F5`). Keep the existing names; do not delete `Purple*`/`Pink*` yet
  (other files may reference them — check before removing).
- Check what actually paints the screen: `core/CoreLayout.kt` hardcodes
  `.background(color = Color.Black)` and `customizedTextStyle` defaults `color = Color.White`.
  Repoint `CoreLayout` at the theme's `background` role. Do not change `customizedTextStyle`'s
  signature — other screens depend on the default.
- `res/values/themes.xml` sets `android:windowLightStatusBar=true`, which is a light-theme setting.
  Set it to `false` so status-bar icons are legible on a dark background. Check `values-v30` too.
- `app_name` → "Calendar Note" in `res/values/strings.xml`. Leave `applicationId` and the
  `com.example.skeleton` package alone.
- Create `README.md` at the repository root: purpose, features, tech stack, and the package tree for
  `app/src/main/java/com/example/skeleton/` with a purpose note per major package, in the ordering
  `CLAUDE.md` requires (subfolders first, then `.kt` files). Every later task updates it in the same
  change that moves a package.

## Notes

- The `Purple80`/`Pink40`-style tokens are Compose-template leftovers. Check for references before
  deleting any of them — removing a referenced token turns a theme task into a compile failure in an
  unrelated file.
- `CoreBottomBar` already hardcodes `Color(0xFF35A0F5)` for its centre button and `Color.White` for

### What was actually done, where it differed from the plan above

- **`Purple80`/`PurpleGrey80`/`Pink80`/`Purple40`/`PurpleGrey40`/`Pink40` were deleted.** The task
  said to check for references first: the only file referencing any of them was `Theme.kt` itself,
  which this task rewrote. Leaving six unreferenced Compose-template purples in `Color.kt` would
  have left a later screen something wrong to reach for.
- **`values-v30/themes.xml` needed no edit.** It overrides only `Theme.JetpackCompose` and inherits
  `Core.Theme.JetpackCompose` from `values/`, which is where `windowLightStatusBar` lives — so the
  `true` → `false` fix propagates to API 30+ automatically. Verified by reading both files.
- **`app_name` was removed from `values-de/strings.xml`.** It is `translatable="false"` in
  `values/`, yet a German copy existed holding the *old* name — so German users would have kept
  seeing "Android Compose Skeleton" after this rename. `translatable` is a lint hint, not a runtime
  one; deleting the German entry is what makes the rename actually take effect in that locale.
- **`PreviewBottomBar` is now wrapped in `MyApplicationTheme` on the theme's background.**
  `CoreBottomBar` reads `MaterialTheme.colorScheme` as of this task, so the bare preview would have
  rendered it against Material's *default* scheme on Studio's white — which `POLICIES.md`
  § User-Interface Defects names explicitly as how hardcoded colours survive review.
- **Four German strings were added** to clear the pre-existing lint failure. See Evidence.
