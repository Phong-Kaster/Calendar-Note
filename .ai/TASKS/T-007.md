# T-007 — Selecting today or a past day shows that day's notes, with an empty state

- **Status:** pending
- **Depends on:** T-006
- **Attempts:** 0 / 3

## Description

Make the calendar selection mean something.

- Selecting today or any past day loads that day's notes through
  `NoteRepository.notesForDateFlow(date)` (backed by the `observeByDate` DAO query added in T-002)
  and shows them in a scrolling list beneath the grid, on the same screen (decision A4 in the DoD).
- Explicit empty state when the selected day has no notes. A blank region reads as a load failure,
  not as "nothing here yet".
- Tapping a note in that list opens it in the Note screen, the same route Home uses.
- The whole screen scrolls: grid plus a variable-length list will not fit on a short device, and a
  fixed-height layout pushes the list — and later the add action — off the bottom.
- Mark days that have notes in the grid. The marker must contrast with the cell fill in **every**
  combination: has-notes on a normal cell, on today's cell, and on the selected cell.

## Acceptance

Maps to the first half of DoD criterion 11.

- Build, unit tests and lint succeed.
- A JVM unit test against a fake DAO proves `notesForDateFlow(D)` returns only notes dated `D`,
  including a case with notes on `D-1` and `D+1` present in the store.
- A unit test proves the has-notes day set is derived from the stored notes, not from the selection.
- Recorded as **needing human inspection** (class (I)): the empty state appears for a day with no
  notes; the screen scrolls with a long list; the has-notes marker is visible on a selected cell and
  on today's cell.
